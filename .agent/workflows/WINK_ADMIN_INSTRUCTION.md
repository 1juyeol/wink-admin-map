## 🛠️ 4. 기술적 금기 및 표준 (핵심 보호)
1. **근본 원인 해결 (Root Cause Logic)**: 가시적인 버그만 가리는 **'뗌질식 수정'을 금지**한다. 데이터가 발생하는 **원천(Hook/Store/API)** 단계부터 시스템적으로 문제를 해결하는 **'정석적인 로직 수정'**을 최우선으로 한다. 
2. **증거 기반 답변 (Evidence-Based)**: 추측성 답변 금지. 반드시 파일을 직접 확인하고 증거를 제시할 것.
3. **코드 무결성 유지 (Clean-Up)**: 작업 완료 후 사용하지 않는 코드 찌꺼기는 즉시 정리할 것.
4. **적극적 선조치 (Proactive Action)**: 단순 루틴 작업(패키지 설치, 빌드 확인 등)은 묻지 말고 **먼저 실행**한 뒤 보고하여 작업 흐름을 끊지 않는다.
5. **상세 제안 및 승인 (Detailed Proposal)**: 코드 수정 전 반드시 **[파일/라인, 수정 근거, 상세 로직]**을 설명하고 사용자에게 허락을 구한다.
6. **친절한 한국어 에러 안내 (User-Friendly Error)**: 에러 발생 시 영문 콘솔 출력 대신 사용자 화면에 **친절한 한국어 메시지 및 조치 방법**을 안내하도록 설계한다.
7. **윈도우 배포 보안**: 배포 시 CMD 창 노출 여부를 반드시 확인하며, 프로그래밍 방식을 지향한다.
8. **사이드바 로직 보호**: `.agent/rules.md`의 사이드바 핵심 로직은 허락 없이 절대 수정하지 않는다.
9. **엑셀 데이터 무결성 (1:1 매핑)**: 원본과 1:1 매핑을 철저히 준수하며 하드코딩된 분해 로직 사용을 엄격히 금지한다.
